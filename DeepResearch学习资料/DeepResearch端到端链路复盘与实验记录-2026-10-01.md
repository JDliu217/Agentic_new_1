# DeepResearch 端到端链路复盘与实验记录

> 日期：2026-10-01
>
> 用途：把源码阅读结果转成可执行的验证任务，并记录每次实验的证据。

## 1. 一次研究请求的时序

```text
React 页面
  -> api.session.deepsearch()
  -> POST /research/stream
  -> research_router
  -> DeepResearchV2Service
  -> DeepResearchGraph.run()
  -> ChiefArchitect
  -> DeepScout
  -> DataAnalyst
  -> CodeWizard
  -> LeadWriter
  -> CriticMaster
  -> asyncio.Queue
  -> SSE
  -> ReadableStream
  -> 研究详情页和最终报告
```

每个箭头都代表一个需要验证的边界。排错时不要只看最终页面，要先确认请求是否到达路由，再确认 Agent 是否写入共享状态，最后确认 SSE 事件是否被前端消费。

## 2. 关键状态字段

| 状态 | 作用 | 验证方式 |
| --- | --- | --- |
| `ResearchState` | Agent 之间传递运行时研究上下文 | 查看节点输入和输出 |
| `state_json` | 保存后端研究状态 | 检查数据库记录 |
| `ui_state_json` | 保存前端恢复所需状态 | 断线后重新打开页面 |
| `final_report` | 保存最终报告正文 | 对比 SSE 完成事件和数据库 |
| 事件队列 | 暂存实时进度和结果 | 检查事件顺序、重复和结束标记 |

## 3. 最小实验矩阵

### 实验 A：正常研究

- 输入：一个需要搜索和总结的行业问题。
- 观察：路由日志、Agent 顺序、SSE 事件、最终报告。
- 通过标准：前端显示阶段进度，结束事件只出现一次，报告可重新加载。

### 实验 B：搜索服务不可用

- 操作：使用无效搜索服务地址或关闭对应依赖。
- 观察：超时是否有限，是否产生明确错误，状态是否标记失败。
- 通过标准：请求不会无限等待，用户能看到失败原因，已有中间结果不会被静默覆盖。

### 实验 C：客户端断线

- 操作：研究进行中刷新页面或关闭连接。
- 观察：后台任务是否继续，`ui_state_json` 是否可恢复，重复订阅是否重复生成任务。
- 通过标准：重新进入页面能够看到当前状态，恢复操作不会产生两个并行研究。

### 实验 D：知识库召回

- 操作：上传一份包含唯一关键词的文档并发起相关问题。
- 观察：解析、切分、嵌入、Milvus 写入和 DeepScout 召回结果。
- 通过标准：能定位唯一关键词来源，并确认不是只返回 Mock 数据。

## 4. 需要特别留意的实现边界

1. V2 当前默认简化运行路径不等于完整 LangGraph `astream()` 节点执行。
2. 文档状态为 `completed` 不自动证明向量写入和召回成功。
3. `resume=True` 需要结合实际持久化逻辑判断，不能仅凭参数名称认为是节点级断点续跑。
4. CodeWizard 若在当前进程使用 `exec()`，必须按非沙箱执行评估文件、网络、环境变量和资源消耗风险。
5. Text2SQL 返回结果时要区分真实数据库查询和不可用时的 Mock 分支。
