# DeepResearch 发布前检查清单

## 1. 代码和构建

- [ ] 后端源码可以通过编译检查。
- [ ] 前端生产构建成功，并确认没有阻断性的类型错误。
- [ ] 本次提交只包含预期文件。
- [ ] 没有把密钥、令牌、数据库密码或本地绝对路径提交到仓库。
- [ ] 新增接口、配置和状态字段已经同步到对应文档。

## 2. 配置和依赖

- [ ] 生产环境变量已逐项准备。
- [ ] LLM、搜索、数据库、Redis 和 Milvus 的地址在部署环境可访问。
- [ ] 超时、重试次数和并发上限符合实际服务额度。
- [ ] Docker Compose 中的服务名称、端口和卷路径已核对。
- [ ] 前端 API 地址与后端实际监听地址一致。

## 3. 核心流程

### 普通聊天

确认登录、会话创建、消息发送、流式返回和历史加载均可完成。

### DeepResearch

确认研究请求能够经过路由、任务拆解、搜索、分析、写作和审查，并通过 SSE 返回进度和最终报告。

### 知识库

确认文件上传、解析、切分、嵌入、Milvus 写入和召回分别有可观测证据。文档状态完成不能单独作为向量写入成功的证明。

### 恢复和取消

确认取消不会继续向前端发送误导性的完成事件；断线后重新进入页面不会重复创建同一个研究任务。

## 4. 安全检查

- [ ] 研究记录、检查点、取消和恢复接口检查用户归属。
- [ ] CodeWizard 的代码执行有超时、资源限制和文件系统隔离。
- [ ] 日志不会输出令牌、完整 Authorization 头或用户私密内容。
- [ ] 外部 URL、SQL 和文件路径经过校验。
- [ ] 错误响应不会把内部堆栈直接返回给用户。

## 5. 可观测性

发布前应能根据一个研究 ID 找到：请求时间、用户、状态变化、Agent 阶段、外部调用、错误原因和最终持久化结果。至少保留成功、失败、取消和超时四类日志样本。

## 6. 回滚准备

- [ ] 已记录上一版本提交号。
- [ ] 已确认数据库迁移是否可逆。
- [ ] 已确认新配置缺失时的回退行为。
- [ ] 已准备关闭异常功能或恢复上一镜像的操作步骤。
- [ ] 已指定发布后观察的指标和时间窗口。
