# DeepResearch 故障排查决策树

## 1. 先判断故障层级

```text
页面无响应？
  ├─ 是：检查浏览器请求、SSE 连接和前端状态更新
  └─ 否：继续看报告内容

请求是否到达后端？
  ├─ 否：检查前端 URL、端口、代理和网络
  └─ 是：继续看路由日志

路由是否创建研究任务？
  ├─ 否：检查认证、参数 Schema 和数据库连接
  └─ 是：继续看 Agent 事件

Agent 是否持续产生事件？
  ├─ 否：检查 LLM、搜索、RAG 和超时
  └─ 是：继续看最终状态

报告是否保存并可重新加载？
  ├─ 否：检查状态持久化和事务
  └─ 是：检查内容质量和引用来源
```

## 2. SSE 相关问题

### 表现：页面一直显示加载中

1. 查看浏览器 Network 中的 `/research/stream` 请求是否保持连接。
2. 确认响应的 `Content-Type` 是 `text/event-stream`。
3. 检查后端是否持续写入带换行的 SSE 事件。
4. 检查事件是否包含前端约定的类型和 JSON 字段。
5. 确认异常路径也会发送结束或失败事件，而不是只记录服务端日志。

### 表现：进度重复或顺序错乱

检查客户端是否重复订阅，服务端队列是否被多个消费者读取，以及前端是否用事件 ID 去重。不要只通过增加等待时间解决事件顺序问题。

## 3. RAG 相关问题

按下面的顺序逐层确认：

1. 文件是否成功上传。
2. 文档解析器是否产生正文。
3. 文本切分是否产生非空片段。
4. 嵌入模型是否返回向量。
5. 向量是否写入 Milvus 目标集合。
6. 查询时使用的集合、维度和过滤条件是否一致。
7. 召回结果是否真的传给 DeepScout 或后续 Agent。

任何一层没有证据，都不能把问题归因到“模型回答不好”。

## 4. Agent 相关问题

检查每个 Agent 的四个边界：

- 输入：它读取了哪些 `ResearchState` 字段？
- 工具：它调用了哪些外部服务？
- 输出：它写回了哪些字段？
- 失败：异常是重试、降级、跳过还是终止？

重点检查字段名称是否前后一致。状态字段拼写错误时，流程可能表面完成，但后续 Agent 得到的是空数据。

## 5. 数据库和恢复问题

如果页面显示研究完成但刷新后报告消失，优先检查：

1. 完成事件发送时是否已经提交数据库事务。
2. `final_report` 是否与研究记录使用同一个 ID。
3. `state_json` 是否能被当前版本代码反序列化。
4. 恢复接口是否校验当前用户和研究记录归属。
5. 重复恢复是否会启动第二个后台任务。
