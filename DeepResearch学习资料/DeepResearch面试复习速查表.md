# DeepResearch 面试复习速查表

## 1. 一分钟项目介绍

这是一个以 FastAPI 和 React 为基础的行业信息研究助手。用户提交研究问题后，后端通过研究路由进入 DeepResearch V2 服务，由多个 Agent 协同完成任务拆解、资料搜索、数据分析、代码辅助、报告撰写和质量检查，再通过 SSE 将进度和最终报告持续推送到前端。系统同时接入知识库、长期记忆、Text2SQL 和行业数据服务。

## 2. 高频追问

### 为什么使用 SSE？

研究过程较长，SSE 可以让服务端持续推送阶段进度、日志和最终结果，前端不必等待一个很长的普通 HTTP 响应。需要同时考虑断线、重复事件、取消和最终状态保存。

### `ResearchState` 是什么？

它是多个 Agent 共享的运行时状态，承载研究问题、任务列表、搜索结果、分析结果、草稿、批评意见和最终报告。它不是数据库本身，长期恢复还需要检查点或持久化记录。

### RAG 链路的关键风险是什么？

上传成功、文档处理完成和向量真正写入并不等价。需要分别确认解析、切分、嵌入、写入、索引和召回，并检查召回结果是否真的被 Agent 使用。

### CodeWizard 的生产风险是什么？

如果代码在当前进程直接 `exec()`，它可能访问文件、环境变量和网络。生产实现应使用隔离容器或专门沙箱，设置资源限制、超时、系统调用限制和输出大小限制。

### 如何处理外部服务失败？

先区分可重试错误、不可重试错误和数据错误；为请求设置超时和重试上限，记录关联 ID，保存中间状态，并向前端发送可理解的失败事件。

## 3. 需要主动说明的边界

- 当前 V2 默认简化运行路径不等于完整 LangGraph 节点级恢复。
- 测试向导中的 Mock 数据不能证明真实搜索链路可用。
- Docker Compose 启动基础设施不代表前后端已经启动。
- 文档状态完成不代表向量库写入和召回一定成功。
- URL 深读的简化抓取不等于真实浏览器渲染。
