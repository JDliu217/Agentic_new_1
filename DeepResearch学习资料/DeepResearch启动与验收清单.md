# DeepResearch 启动与验收清单

## 1. 启动前检查

- [ ] 已确认 Python、Node.js 和 npm 版本满足项目要求。
- [ ] 已准备环境变量，并检查密钥没有写入源码或提交历史。
- [ ] 已确认 PostgreSQL、Redis、Milvus 等基础设施的地址和端口。
- [ ] 已确认真实 LLM、搜索、股票和招投标接口的配置。
- [ ] 已阅读 Docker Compose，知道它启动哪些服务，哪些服务仍需手动启动。

## 2. 静态验证

- [ ] `python -m compileall -q app` 通过。
- [ ] 前端 `npm run build` 通过。
- [ ] 路由、Schema、模型和配置文件能够互相对应。
- [ ] V1 与 V2 的入口、HTTP 方法和返回协议已确认。
- [ ] 已检查前端端口配置和文档中的端口是否一致。

## 3. 最小运行验证

先验证最短路径，再验证完整研究流程：

1. 健康检查和基础 API。
2. 登录、会话创建和普通聊天。
3. 文件上传、文档状态和知识库检索。
4. `POST /research/stream` 的 SSE 事件顺序。
5. 最终报告生成、保存和前端展示。
6. 取消、失败和恢复路径。

每一步记录请求、响应、日志、依赖服务状态和数据库变化。

## 4. 重点风险

| 检查项 | 需要确认的事实 |
| --- | --- |
| 权限 | 研究、检查点和取消接口是否校验当前用户归属 |
| 状态 | `state_json`、`ui_state_json`、`final_report` 是否保持一致 |
| 检索 | 文档完成是否真的写入 Milvus，DeepScout 是否能召回 |
| 执行 | CodeWizard 是否运行在受限沙箱，而不是直接使用进程权限 |
| 恢复 | `resume=True` 是否真正从节点断点继续 |
| 降级 | LLM、搜索或数据库不可用时是否明确返回错误 |
