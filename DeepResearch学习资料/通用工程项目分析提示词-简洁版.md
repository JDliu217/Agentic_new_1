# 通用工程项目分析提示词（简洁版）

复制下面的提示词到新聊天，把项目路径和资料保存路径替换成自己的即可。

```text
请阅读并讲解这个工程项目，帮我建立从项目全貌到核心源码的理解，并把学习资料保存为一组 Markdown 文件。

项目路径：[填写项目路径]
资料保存路径：[填写输出路径]

请先扫描项目，再决定分析重点。不要预设项目使用某种技术，也不要把不存在的组件硬套进分析；例如，只有源码里确实存在时才讲 RAG、消息队列、SSE、数据库或模型训练。

分析时请以实际源码、配置、脚本和测试为依据。先说明项目解决什么问题、如何启动、主要目录和模块如何协作；再沿着真实入口追踪最重要的请求、任务或数据流程。对核心模块说明职责、入口、关键类或函数、输入输出、依赖关系、状态和错误处理。第三方代码与项目自有代码要区分。

请只读原项目，不改源码。能安全运行的检查可以执行；无法运行的地方，说明缺少什么以及因此不能确认什么。明确区分源码确认、实际运行验证、推断和未验证结论，不要把环境缺失说成代码错误。

根据项目规模安排文档数量，避免重复凑篇数。至少提供项目总览、架构与目录、核心流程、重要模块、运行配置、验证结果和问题清单，并建立一个索引说明推荐阅读顺序。每份专题资料都列出对应源码路径，并留出笔记和自测题的位置。

完成后检查文档是否覆盖了项目的主要自有模块和关键流程；列出未覆盖或未验证的内容及原因。不要只给我分析计划，请直接完成扫描、分析和文档生成。
```

## 为什么这版适合不同项目

- 先扫描再选重点，不预设项目类型。
- 流程名称来自真实入口和代码，不照搬固定清单。
- 项目规模决定文档拆分粒度，减少重复内容。
- 结论带证据边界，方便区分读懂源码和真正跑通。
